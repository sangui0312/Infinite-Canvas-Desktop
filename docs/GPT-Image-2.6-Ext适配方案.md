## 3. 当前官方参数契约

| 项目 | 接入规则 |
| --- | --- |
| 接口 | `POST /v1/images/generations`，JSON 请求体 |
| 模型名 | `gpt-image-2.6-ext` |
| 版本 | `flare`、`sunburst`，默认 `flare` |
| 分辨率 | 当前仅 `1k`，`2k` 和 `4k` 会返回未配置价格错误 |
| 比例 | `auto` 和 10 种支持比例，禁止向上游发送像素尺寸 |

| 质量 | `auto`、`low`、`medium`、`high`、`xhigh`、`max`，未指定时省略 |
| 格式 | `png`、`jpeg`、`webp`、`svg`、`gif`，`jpg` 规范为 `jpeg` |
| 复杂度 | 可选 `low`、`medium`、`high`，未指定时省略 |
| 参考图 | 最多 16 张，每张不超过 20 MB，PNG/JPEG/WebP/GIF/BMP |
| 参考图地址 | 公网 HTTP(S) URL 或图片 Base64 Data URL |
| SVG | 仅文生图，可指定支持的比例，可选 SVG 编写模型及推理档位 |
| GIF | 仅文生图，`size` 和 `aspect_ratio` 只能省略或为 `auto` |

| 查询 | 从 `data[0].task_id` 取任务号，每 3～5 秒查询已有任务 |
| 成果 | 读取 `result.images[*].url` 的链接数组，并按实际格式转存 |

10 种比例为 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`5:4`、`4:5`、`21:9`。

以上限制取自当前官方文档。后续上游开放新档位时，应更新模型能力定义和验收用例。[官方参数说明](https://docs.apimart.ai/cn/api-reference/images/gpt-image-2.6-ext/generation.md)

## 5. 后端请求与参数处理

### 5.1 独立能力定义

新增精确的 2.6 Ext 判断及规范化函数。后端能力定义用于参数 schema、请求校验和 Agent，前端使用一份共享的 2.6 Ext 参数工具，供在线生图与两个画布复用。

能力至少包含模型名、版本、比例、分辨率、质量、格式、复杂度、参考图数量和不同格式的组合限制。

2.5 Ext 与 2.6 Ext 各自使用能力定义和序列化规则，避免将 2.5 的背景选项、2K/4K 和参考图逻辑混入 2.6。

### 5.2 请求字段

在 `OnlineImageRequest` 和对应调用链增加 `complexity`、可选 `svg` 配置，并传到 `generate_ai_image`。`svg` 使用受约束结构，只接受文档声明的模型和推理配置字段。

请求由允许字段组装，统一处理大小写及首尾空格。只发送一个尺寸字段，使用 `size`。普通图片默认 PNG，质量及复杂度未设置时省略。

典型图生图请求为

```json
{
  "model": "gpt-image-2.6-ext",
  "version": "sunburst",
  "prompt": "保留商品和包装文字，调整布景",
  "resolution": "1k",
  "size": "3:4",
  "quality": "high",
  "output_format": "png",
  "n": 1,
  "image_urls": ["data:image/png;base64,..."]
}
```

当前背景控制不列入 2.6 Ext 的有效参数。若旧节点带有背景或压缩默认值，规范化时剔除这些无效字段。PNG/WebP 成果按上游实际透明通道保存。

### 5.3 参考图

- 提交前验证数量，超过 16 张明确提示，不截断。
- 本地文件和 Data URL 验证实际格式与字节数，校验最终发送内容满足单张 20 MB 限制。
- 保持参考图的顺序。GIF/BMP 等合法输入在 2.6 专属路径按实际可支持内容处理，避免无提示的动画扁平化。
- 公网 URL 保持上游可访问形式，远程文件限制由上游最终验证，失败时展示对应原因。
- 上游文档未声明 `asset://`，该形式在本地解析转换为合法输入或在提交前提示处理。
- 任一参考图读取失败时暂停该项生成，显示失败图片，不发送缺图请求。

### 5.4 旧节点与历史设置

历史像素尺寸只在本地用于换算支持比例。接近支持比例的历史取整尺寸可沿用既有容差规则，换算结果展示在参数区。

显式保存的 2K/4K 或不支持比例显示待调整状态，由用户重新选择。初次切换到 2.6 Ext 时采用该模型默认的 1K、PNG、Flare，界面同步刷新。

GIF 与固定比例、SVG/GIF 与参考图的冲突，在提交前显示具体问题，保留输入供调整。

## 6. 适配尺寸与循环输入

保留“自动比例”和“适配输入尺寸”两种现有使用意图。

### 自动比例

向上游发送 `size=auto`。按照官方定义，文生图输出方图，图生图由第一张可读参考图选择最接近的支持比例。界面显示“自动”，成果显示实际像素。

### 适配输入尺寸

每次执行读取本轮实际引用图片的宽高，再匹配支持比例，明确显示本轮最终请求的比例和 1K。仅上游支持比例可以作为请求值，原图像素尺寸用于本地判断。

优先复用现有输入图序号规则。普通画布尊重已选择的适配参考图，智能画布和 Agent 沿各自现有引用顺序解析。读取失败时显示待补充或错误状态，避免复用上一轮比例。

匹配规则在前后端共用同一约定，采用既有 Ext 的相对比例误差计算和固定候选顺序。对非标准原图，界面将映射后的比例作为有效请求值展示。上游 `auto` 的内部匹配算法未公开，本地适配使用明确比例保证请求可核对。

### 循环与并发

- 平铺循环在每一轮重新计算尺寸，并创建独立参数快照。
- 按组循环以本轮分组内选定图片为尺寸依据，参考图序号越界时明确提示当前输入。
- 一次输入横图、方图、竖图时，应分别得到本轮对应的支持比例。
- 图片并发沿现有设置执行，按组循环继续使用现有最多 2 路规则。
- 每个上游请求始终 `n=1`。UI 的多张数量代表多个任务，集中在现有入口的一个层级拆分。
- 成功结果逐项落盘和回填。部分任务失败时保留已成功成果，重试定位到失败项。

## 8. SVG/GIF 成果处理

### 正确保存与元数据

- 根据实际响应类型和文件内容保存 `.png`、`.jpg`、`.webp`、`.svg` 或 `.gif`，保留原始文件字节。
- 下载到临时文件，完整验证后提交最终文件，失败时提供继续下载已有成果的入口。
- GIF 保留动画帧，记录尺寸与动画属性，画布和预览使用原 GIF。
- SVG 读取明确宽高或 `viewBox`，原文件用于下载，画布使用安全预览。
- 元数据记录实际格式、MIME、原件地址、预览地址及上游任务号。

### SVG 安全预览

SVG 可能包含脚本、事件、外部引用和交互内容。预览使用经过清理的 SVG 或安全生成的位图，禁止内联执行上游 SVG。原文件下载通过附件响应交付，核对其访问路由和响应头。

预览需要的限制包含脚本、事件属性、`foreignObject`、外部资源和 XML 外部实体。无法安全生成预览时显示文件卡片并保留原件下载能力。

### 下游操作和素材生命周期

裁剪、遮罩、压缩、拼接和作为参考图继续生成需要位图输入时，显式生成派生 PNG，记录其来源。GIF 的取帧操作明确为静态派生图。

素材目录、引用扫描、删除、撤销、回收站和自动清理识别原件与派生预览的关联。有引用的成果及其必要预览都受保护，重复预览生成应复用已有文件。

项目导出携带原件和必要预览，导入恢复引用路径。普通下载和批量 ZIP 提供原始格式，GIF 动画和 SVG 源文件在保存、重开及导入后可继续使用。

## 9. 异步任务与 Agent
