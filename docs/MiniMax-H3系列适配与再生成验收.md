# MiniMax-H3 / H3-Max 适配与再生成验收

本次在独立桌面端工作区实施，基于已发布的 1.1.0 源码，作为 1.1.1 发布；未改动原 Web 项目和用户安装目录。安装包、更新路线与公开下载校验见 desktop-1.1.1-verification.md。

## 模型适配

| 项目 | MiniMax-H3 | MiniMax-H3-Max |
|---|---|---|
| 时长 | 4～15 秒 | 5～15 秒 |
| 分辨率 | 768P、2K；默认 2K | 480P、768P、1080P；默认 768P |
| 首尾帧比例 | 跟随输入，界面显示跟随首尾帧 | 跟随输入，界面显示跟随首尾帧 |
| 参考模式 | 图片、视频、音频；图片与视频可以组合 | 相同 |
| 水印 | 传递用户设置 | 480P/768P 传递；1080P 省略字段 |
| Regeneration | 成功的 768P 结果可手动升级 | 禁止 |

普通画布、智能画布和 Agent 共用后端校验。超量素材、纯音频、首尾帧与参考视频/音频混用会被阻止；图片上传部分失败时停止提交，避免缺图生成。两个画布按模型显示分辨率和时长范围，Max 获得与 H3 相同的实际尺寸及比例异常提示。

外部 URL 的文件完整性、格式及媒体总时长仍由上游执行最终校验。本次没有增加远程媒体的主动下载探测，也没有改变原有本地参考视频裁剪和上传流程。

## 768P 升至 2K

1. H3 选择 768P，生成后按原流程保存并立即显示，不自动接着执行再生成。
2. 普通画布结果视频下方、单素材右键菜单及智能画布视频操作栏提供“升至 2K”。只有保存了原任务信息的 H3 768P 结果显示入口。
3. 用户确认额外计费后，后端核对原任务完成状态，以 `MiniMax-H3-Regeneration` 与 `source_task_id` 提交，不重新上传素材。
4. 入口显示核对、提交、生成、保存、完成或失败状态。原 768P 保持可用，2K 作为独立关联结果加入画布；两个结果分别保留自己的任务 ID。
5. 直接选择 H3 2K 仍直接生成 2K；Max 不显示升级入口。旧“高清”开关不再用于这两个模型；旧客户端直接发送自动升级参数时给出明确错误，不静默触发额外付费任务。
6. Agent 的 H3/Max 参数契约及成果元数据传递一并适配；正常交付的 H3 768P 成果保留后续升级所需信息，Agent 本身不会自动执行额外付费升级。

## 任务持久化和重试

- 在个人数据目录的 `data/minimax_video.sqlite3` 保存原任务摘要和升级任务。跟随现有个人数据迁移、备份流程；不写入安装程序目录。
- 不保存 API Key。用不可回显的账号指纹绑定源任务与升级任务；更改凭据后须切回原凭据查询既有任务。
- 相同平台、凭据和源任务复用同一条升级记录，重复点击不会重复提交。
- 提交前先落盘“提交中”，拿到任务 ID 后立即保存。响应丢失或进程中断而没有任务 ID 时，显示“提交待核对”，禁止自动重提，用户到 APIMart 核对。
- 已有升级任务 ID 时，网络、查询或下载失败只恢复查询与保存，不重新生成。明确被拒绝或上游明确生成失败后，用户再次确认才允许重试升级。
- 保留原 768P；升级失败不会删除、覆盖或重新生成原片。新结果加入画布支持现有撤销流程；任务完成时原节点已删除，不自动恢复被删除节点。
- 智能画布保存会复制素材对象，控制器按源任务和素材 URL 重新定位当前对象，避免状态停在旧对象、成果交付丢失。

## 验证

- Node 自动检查：88 项通过（含本次模型控制、确认取消、重复点击、响应丢失、恢复查询及素材对象替换检查）。
- Python 后端：138 项通过；本次新增和关联检查覆盖参数、参考组合、任务持久化、账号绑定、确认、未知提交、下载恢复与 Agent 成果传递；最终数量见 `.test-data/minimax-all-python-tests.log`。
- 实际 Electron 窗口：使用随机本地端口、独立临时个人数据、人工合成短视频和完全模拟的上游；验证两个画布的入口、进度、原片保留、独立 2K 结果、保存重新打开、Max 分辨率/水印控制及首尾帧比例提示。
- 上游模拟提交两次，分别对应普通画布和智能画布；没有连接真实生成接口、没有产生费用、没有迁移或清理真实个人文件。
