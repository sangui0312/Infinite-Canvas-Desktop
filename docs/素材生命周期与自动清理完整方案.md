# 素材生命周期、删除撤销与自动清理方案

方案状态：源码实施完成，尚未打包、安装或发布。

适用项目：`E:\running hub\desktop-app` 的 Windows 桌面版。本文只定义实施方案，不修改原 Web 项目、不操作真实个人素材、不发布更新。

## 1. 目标和基本规则

解决图片、视频在删除节点后持续占用磁盘的问题，同时保证画布、聊天、任务、撤销及备份恢复不会因为清理而丢失素材。

本方案统一四种不同操作：

1. **移除引用**：从节点、记录或收藏中移除素材，不立即删除文件。
2. **移入素材回收站**：可恢复的文件删除，只对软件拥有的副本执行。
3. **恢复素材**：恢复文件及相关条目；恢复引用时取消自动清理资格。
4. **永久删除**：回收站到期且没有保护关系后删除文件，或用户在明确确认后手动执行。

不可改变的规则：外部原文件不自动删除；任一有效引用或使用保护存在时不删除；读取不完整时不把素材判断为无引用；不按文件年龄、大小或磁盘访问时间直接删除。

## 2. 已检查的现状

以下结论来自当前桌面项目源码，不代表已扫描或处理用户实际资料。

| 操作 | 当前行为 | 本次应如何调整 |
| --- | --- | --- |
| 拖入、上传图片或视频 | 上传到软件管理目录形成副本；外部原文件不移动 | 登记副本及来源类型，外部路径仅作来源说明，不成为删除目标 |
| 复制粘贴、导入本地图片路径 | 通常写入或复制为新的输入文件 | 与拖入文件采用同一登记流程 |
| 生成图片、视频 | 保存本地结果；视频先下载和校验 | 写入成功后登记，任务完成并交付前保护 |
| 裁剪、拼接、扩图、图层拆分、3D 导出等 | 产生新文件或派生结果 | 登记各个输出，记录来源关系，执行期间保护输入和输出 |
| 复制节点、多处引用 | 可复用同一地址 | 只增加引用，不因一个节点删除就删除文件 |
| 删除普通或智能画布节点、节点结果 | 主要移除引用，保留文件 | 保持行为，同时更新引用与撤销保护 |
| 删除画布、恢复画布 | 画布进入回收站，仍保存节点数据 | 回收站里的素材引用继续有效 |
| 永久删除画布、过期画布清理 | 删除画布记录 | 移除该画布引用；文件重新计算未引用时间，不直接连带删除 |
| 删除项目 | 将项目下画布迁回默认项目 | 不删除素材，不重置其引用身份 |
| 加入资产库 | 常规加入流程创建 library 副本 | 资产库条目作为主动保留关系，记录副本与原素材为不同文件 |
| 删除资产条目、资产分类或库 | 存在直接删除文件、分类目录的路径 | 统一经过引用检查和回收站；禁止直接整目录递归删除 |
| 删除本地素材、存储文件 | 当前可直接删除文件 | 统一经过安全删除服务；检查配套说明和分类文件 |
| 删除生成历史 | 当前会尝试删除历史中的图片文件 | 优先修改：只移除历史关系，仍被画布使用的文件必须保留 |
| 删除聊天记录、聊天会话 | 涉及附件和生成结果引用 | 保存变更后更新引用，不连带删除仍有其他使用者的文件 |
| 重命名、移动本地素材 | 部分接口直接修改磁盘路径 | 接入稳定素材标识和地址解析，避免旧画布地址失效 |
| 项目、画布、工作流导入导出 | 复制、打包文件，重写资源地址；有仅含引用的情况 | 任务期间保护资源；导入建立新引用；导出不视为解除引用 |
| 从旧 Web 导入 | 下载资源并改成本地地址 | 下载、待提交、可恢复导入任务均受保护 |
| 浏览器预览、下载、外部保存 | 读取文件或另存副本 | 活跃读取短期保护；用户另存的外部文件不纳入清理 |

已确认需统一的直接删除入口包括 `/api/history/delete`、`/api/local-assets/delete`、`/api/storage-files/delete`、资产库条目批量删除及分类/库删除。实施前还需核对这些入口的全部调用方与文件处理函数，区分用户文件和失败任务临时文件，不能批量替换所有 `os.remove`。

## 3. 素材管理范围

### 3.1 自动清理范围

首版只处理软件登记拥有的图片、视频文件：输入副本、生成结果、导入副本，以及明确登记为独立文件的编辑输出。新文件写入成功后登记；旧文件通过只读扫描建立目录。

资产库内有有效条目的文件视为主动保存，不因没有画布引用而自动清理。未登记、格式无法确认、存在异常路径或归属不清的文件只列入“待核对”，不删除。

### 3.2 默认排除

- 外部拖入来源、共享文件夹、用户下载或导出到其他目录的文件。
- 自定义输入/输出目录：首版不自动纳入，即使它们能通过软件地址访问；之后必须单独明确启用管理，不能因配置过目录就获得删除整目录的权限。
- 程序文件、API 配置、任务数据库、项目 JSON、工作流定义、日志、安装包、备份和迁移备份。
- 音频、文档、PSD 和其他未列入首版自动清理类型的文件；它们仍可参与引用保护，后续另行扩展清理范围。
- 符号链接、目录联接、重解析点、指向管理根目录之外的路径；多硬链接文件也跳过自动删除。
- 上传、下载、编辑中的临时文件。它们由独立失败任务清理规则管理，不能混入普通素材到期规则。

## 4. 引用的认定

“没有画布节点”不等于“没有引用”。需要检查以下来源：

| 引用来源 | 保护规则 |
| --- | --- |
| 所有项目的普通、智能画布 | 任意节点、分组、节点历史、输入输出、参考素材、遮罩和导演台导出中存在引用即保护 |
| 画布回收站 | 未永久删除的画布继续保护素材 |
| 未保存的画布和输入区 | 打开的编辑会话提交当前引用集合，防止仅检查落盘数据漏掉素材 |
| 撤销、重做与待提交快照 | 快照中仍可能恢复到的素材均保护；以各画布实际支持的历史集合为准 |
| 聊天、在线生图及生成历史 | 附件、结果、对比图等仍保存在记录中的素材继续保护 |
| Agent | 消息引用、计划、任务输入、执行结果、交付、恢复及可撤销动作中的素材继续保护 |
| 资产库及保存的工作流 | 明确条目、工作流中的本地素材属于持久引用 |
| 进行中任务 | 上传、生成、编辑、复制、导入、导出、文件读取过程建立临时使用保护 |
| 手动保留 | 用户标记“始终保留”的素材不进入自动清理 |

派生关系分为两类：可独立使用的扁平结果只记录来源信息，不永久锁住全部上游；仍需原素材才能继续编辑或恢复的组合项目必须保存实际依赖引用。不能把所有来源链当成永久引用，否则将永远无法释放空间。

首版采用保守原则：历史记录仍存在就保护其中素材。若历史数据很多导致释放空间有限，提示对应占用来源，由用户先移除历史记录；不能悄悄忽略历史引用。

## 5. 登记与引用检查实现

### 5.1 数据结构

新增独立素材管理模块和 SQLite 数据库，建议存放于当前个人数据目录的 `userdata/data/media_catalog.sqlite3`，不借用 API 配置或 Agent 数据库。

建议记录：

- `assets`：素材 ID、管理根目录 ID、相对路径、类型、大小、修改时间、可选校验值、来源、创建/发现时间、首次确认未引用时间、状态、保留标记。
- `aliases`：旧地址、历史地址及规范化地址到素材 ID 的映射，保证旧画布兼容。
- `references`：素材 ID、来源类型、来源 ID、来源版本、扫描批次。
- `leases`：编辑会话或任务的使用保护、心跳时间、会话状态。
- `trash_operations`：原位置、回收站位置、配套文件、移入原因、时间、状态与恢复信息。
- `scan_runs` 和 `operations`：扫描覆盖范围、错误、操作阶段和恢复记录。

大小和修改时间用于快速检测变化；首次登记、恢复冲突或最终文件身份存在疑问时计算校验值。内容相同不等于同一素材，首版不做磁盘去重，也不合并外部原图与软件副本。

### 5.2 地址兼容

统一识别 `/assets/`、`/output/`、`/api/storage-files/`，以及已知本机地址前缀；解析查询参数、URL 编码和 Windows 路径大小写，最终以受管根目录及文件身份判断引用。

不能仅按文件名匹配，不能随意删除远端地址的主机名后将其当成本地文件，不能在规范化时允许 `..`、二次解码越界或目录联接逃逸。

现有项目先保留 URL 字段，通过别名表兼容；新记录可额外保存 `asset_id`。新客户端移动、重命名文件后，旧地址经映射找到新位置。先保证解析与恢复能力，再逐步写回新地址，不首次启动时批量改写全部项目。

### 5.3 引用来源与完整性

引用索引是加速查询的缓存，真实画布、历史和任务记录仍是依据。保存成功时增量更新引用，并定期做全量复核。扫描读取对应格式的已知字段并保守收集嵌套媒体地址；未知结构列为不完整，不把“没解析到”当成“未引用”。

单个画布或数据库读取失败、数据迁移中、数据盘离线、索引损坏、引用来源版本变化未完成检查时，该批自动删除暂停。索引删除后能从真实数据重建，重建完成前不执行删除。

## 6. 自动清理规则

推荐默认设置：自动清理关闭；未引用保留 30 天，可选 7/30/60/90 天；素材回收站保留 7 天。

合格文件必须同时满足：

1. 位于允许管理的根目录，属于软件副本且为首版支持类型。
2. 全量扫描完整，所有持久引用均为零。
3. 没有编辑、撤销、任务、导入导出、读取或手动保留保护。
4. 从首次完整确认未引用开始，连续超过所选期限。
5. 最终操作前重新核对文件身份、引用与使用保护，结果没有变化。

重新被引用时清空未引用计时。以后再次失去全部引用，从新的确认时间重新计算。预览、文件访问时间和打开资源管理器不替代引用关系。

程序启动后延迟约 5 分钟，在资料状态稳定时检查是否需要扫描；之后每天最多自动执行一次，优先空闲时运行。软件关闭时不运行独立清理服务，不创建系统定时任务。首次启用只做扫描并开始观察期，不立刻清掉旧文件。

关闭自动清理同时停止新的自动移入及回收站自动永久删除；已经开始的单文件事务完成或安全回滚。用户仍可手动预览和清理。缩短保留期限后先展示新的候选集合，下次自动执行至少延迟 24 小时，避免改设置瞬间大批删除。

不设置“空间不足时无视引用强制删除”。空间不足只通知用户，不扩大清理范围。

## 7. 删除、撤销、重做与恢复

### 7.1 删除画布节点

保持现有体验：删除节点或结果只移除当前引用，保留文件。删除前的快照加入撤销保护；其他画布仍使用时继续保护。

撤销时先确认素材可用，再恢复节点；若素材恰在回收站，先恢复文件及映射，再提交画布恢复。恢复失败时明确显示缺失素材，不假装完整成功，也不覆盖当前画布。

重做再次移除引用，但仍考虑其他撤销/重做快照。只有快照真正淘汰、画布状态保存完成且其他引用消失后，才开始未引用计时。

首版不扩展现有撤销历史的保存期限：关闭应用后原本不能撤销的操作，不承诺升级后能跨重启撤销。素材回收站恢复是独立能力，不能与画布操作撤销混为一谈。

### 7.2 未保存会话与异常退出

前端按会话提交当前画布、待提交快照和可恢复历史中的引用集合，使用递增版本号和心跳；后台保持持久保护记录。清理与新的素材获取、保存操作经过同一协调入口。

正常关闭时先完成保存，再释放会话保护。异常失联不能因为心跳超时就立即删除：保留最后一次引用集合，至少延长一个完整未引用保留周期；再次打开时先核对未完成保存/恢复状态，再解除保护。无法证明已释放的会话，列为“保护待核对”。

### 7.3 从资产库、历史或本地素材删除

所有入口调用统一服务，先区分“移除当前条目”和“删除文件”。移除当前条目后，若还有其他引用，文件继续保留并提示使用位置；没有其他引用且用户明确要求删除文件时，移入素材回收站。

有画布或任务使用的文件不提供首版“强制删除”按钮。删除分类或库时逐项处理，不递归删除整个目录；部分文件受保护时返回已处理、保留与失败明细。

手动删除操作记录相关条目快照，支持从素材回收站恢复。批量操作每项独立记录结果，不以一次部分成功报告全部成功。

### 7.4 回收站

回收站与画布回收站分开，列出名称、缩略图/类型、大小、原位置、删除原因、删除时间和到期时间，支持恢复、批量恢复、永久删除。

同一文件恢复原路径时不覆盖已有内容：若原路径冲突，恢复到唯一新路径，更新素材别名并提示用户；与本次操作关联的条目按记录恢复，不覆盖用户后续手动编辑。

到期永久删除之前再次检查引用、读取和恢复中的保护。若产生新引用，优先恢复或保留，不继续删除。用户手动永久删除需明确二次确认；仍有引用的文件禁止永久删除。永久删除不可通过撤销恢复，界面必须说明。

配套说明和分类文件与所属素材作为一组进入回收站及恢复；共享配套资源先检查其他所有者。缩略图等可重建缓存与原素材分开管理。

## 8. 文件安全、并发及故障恢复

- 清理前解析最终绝对路径，验证处于登记的受管根目录，拒绝路径穿越、重解析点和归属不明文件。执行和恢复时都检查，不只在预览时检查。
- 清理服务串行执行文件删除事务；素材保存、引用更新、任务使用登记与最终清理在相同协调机制下重新验证，防止扫描后新增引用的竞态。
- 活跃流式读取持有短期保护，避免视频播放、导出或下载过程中移动文件。
- SQLite 与文件系统不能视为同一事务。先持久化操作记录，再移动文件，最后提交状态；每一步可重试，程序启动时恢复未完成操作。
- 回收站优先放在受管根目录同一磁盘的专用隐藏目录，避免跨磁盘搬移失败；该目录从普通素材扫描排除，不能由目录导入重新登记。归属文件和操作记录防止清理其他安装的回收站。
- 文件在预览后被修改或替换时取消本次清理，不能删除同名的新文件。路径冲突、占用、权限不足、数据库失败均保留文件并报告失败。
- 导入、生成写入先使用临时文件，校验完成后原子提交并登记；清理看不到半写入文件。最终写入与登记失败必须留下可恢复记录。
- 多个窗口共享引用检查；同一数据目录被多个进程同时打开时，无法取得协调锁就禁用自动删除。
- 数据路径迁移期间停止清理，连同素材登记和回收站一起校验迁移；旧迁移备份不纳入清理。
- 日志只记录素材 ID、阶段、数量和受控错误码，不记录 API Key、完整远端签名地址、提示词或图片内容。

## 9. 设置与操作界面

在“更多设置 → 数据存储”增加“素材清理”，沿用现有样式，不重做画布布局。

显示：自动清理开关、未引用保留期限、回收站保留期限、上次成功扫描时间和扫描状态、预计可清理空间，以及“扫描预览”“手动清理”“素材回收站”入口。

扫描结果分为可清理、仍被引用、主动保留、暂时保护、无法确认五类。用户可查看引用位置并跳转画布或相关记录；不能解析的引用显示来源和原因，不显示为零引用。

预览的空间数字区分“移入回收站大小”和“永久删除后预计释放空间”。移入同盘回收站并不会立即释放磁盘空间，不能使用误导性提示。

删除入口保留现有操作位置，但对涉及文件的操作明确使用“移除条目”“移入素材回收站”“永久删除”。简单删除节点不弹额外确认框。

## 10. 建议接口与模块归属

接口名称为方案建议，实施时与现有会话校验及错误格式保持一致：

| 接口 | 作用 |
| --- | --- |
| `GET/PUT /api/media-cleanup/settings` | 查询和保存清理设置 |
| `POST /api/media-cleanup/scans` | 启动可取消的只读扫描，返回任务 ID |
| `GET /api/media-cleanup/scans/{id}` | 查询进度、覆盖范围、候选及不确定项 |
| `GET /api/media-assets/{id}/references` | 查看引用来源 |
| `POST /api/media-cleanup/actions` | 对预览版本执行移入回收站，逐项重新验证 |
| `GET /api/media-trash` | 列出素材回收站 |
| `POST /api/media-trash/restore` | 幂等恢复文件及关联信息 |
| `POST /api/media-trash/purge` | 经确认和再次验证后永久删除 |
| `PUT /api/media-sessions/{id}/references` | 编辑会话引用及撤销保护同步 |

所有变更接口要求本机会话授权、来源检查和操作 ID；扫描任务、批量动作有数量限制及分页。前端提供的文件路径不能直接变成删除目标，后台只接受已登记素材 ID 或受控旧接口参数。

后端分离素材目录、地址解析、引用适配器、回收站事务、扫描调度等模块，`main.py` 只保留路由接入。优先沿用现有可随桌面程序更新分发的运行模块组织方式；不为适配旧补丁白名单把危险文件操作散落到前端。

前端改动覆盖普通/智能画布的使用保护与撤销、素材/资产面板、历史删除和数据存储设置。Agent 使用独立适配器读取其已有消息、任务、动作及事件，不修改其原始记录格式。

## 11. 旧数据、更新与回退

1. 开发和验证使用独立测试数据，不直接在用户目录试删。
2. 首次启用只登记和扫描，不改写现有项目，不移动文件；历史素材从首次确认未引用时计时。
3. 保持原 URL 的读取兼容；含未知地址或缺失文件的旧项目显示待核对，不能导致其他文件被判为可删除。
4. 新版设置默认关闭，不因软件更新或数据迁移自动开启。
5. 回收站操作使用可读恢复清单；回退旧版前先在新版停用清理并恢复需要保留的文件。不能承诺旧版认识新版回收站或路径别名。
6. 数据库升级前备份，升级失败保持关闭；索引可重建，删除事务日志和回收站清单不能当普通缓存删除。
7. 涉及桌面基础文件、新模块分发或数据协议时单独判断发布方式，旧客户端无法覆盖的文件不能宣称已由小补丁完整更新。发布需另行授权。

## 12. 实施阶段

### 第一阶段：统一引用与安全删除

建立目录、地址解析和引用适配器；接入直接删除入口，增加回收站、恢复记录和只读预览。检查移动、重命名及历史删除的关联影响。此阶段不启用自动删除。

完成标准：同一文件在两个画布、历史和资产库中复用时，任何一个删除入口都不会破坏其他使用者；异常退出可恢复操作；外部原文件不受影响。

### 第二阶段：画布会话、撤销和任务保护

接入普通/智能画布当前状态、实际撤销/重做快照、Agent 和各种读写任务。处理跨窗口、未保存数据、异常失联、撤销时恢复文件以及路径冲突。

完成标准：删除节点后可正常撤销；任务进行中、尚未保存或素材还在可用撤销历史中时，任何清理都不能移除文件。

### 第三阶段：启用可配置的自动清理

接入 30 天观察期、7 天回收站、调度、取消、再次验证及设置界面。先用模拟时钟和独立数据验证到期流程，确认后才允许用户开启真实自动清理。

完成标准：只有完整确认且持续未引用、无任何保护的受管图片视频，才按设置移入回收站并最终释放空间。

三阶段属于同一完整目标，分阶段实现和验证；未经单独确认，不进行真实资料试删、安装覆盖或发布。

## 13. 验收场景

| 场景 | 必须结果 |
| --- | --- |
| 拖入外部图片/视频，删除节点后到期清理 | 仅软件副本进入回收站，外部原文件及其他文件保持不变 |
| 同一文件用于两个画布，删除其中一个 | 不清理，能列出剩余引用位置 |
| 删除节点后撤销、重做，再撤销 | 引用、文件和画布状态一致，不出现恢复节点但文件丢失 |
| 未保存画布、输入框参考图、有效撤销快照 | 仍受保护，不能仅凭落盘画布判断无引用 |
| 浏览器异常退出，随后启动清理 | 失联保护不立即失效，等待恢复或完整保留周期 |
| 删除历史，图片仍在画布中 | 只移除历史记录，文件和画布预览保留 |
| 删除资产分类，部分文件被其他画布引用 | 逐项报告，受引用文件保留，不递归误删 |
| 视频正在播放或文件正在导出 | 保护使用中的文件，读写结束后再判断 |
| 生成、裁剪、拆层、导演台导出、Agent 待交付 | 输入、输出及恢复所需依赖不会被并发清理 |
| 导入尚未完成、可恢复导入任务 | 下载资源不被认定为孤立垃圾 |
| 同名文件分属不同目录、URL 编码或地址别名 | 准确映射文件身份，不误合并、不漏保护 |
| 重命名/移动后打开旧画布或执行撤销 | 旧引用仍可解析，文件不丢失 |
| 回收站恢复遇到同名新文件 | 不覆盖新文件，安全恢复到新路径并更新映射 |
| 扫描后新增引用或替换同名文件 | 最终检查取消清理 |
| 一个画布损坏、Agent 数据库锁定、目录离线 | 批次暂停删除，明确显示覆盖不完整 |
| 文件移动后数据库提交失败、断电重启 | 根据事务记录恢复一致状态，不丢文件、不重复删除 |
| 目录联接、硬链接、多进程、其他安装资料 | 自动清理跳过或禁用，不越界、不跨安装删除 |
| 调低期限、关闭开关、修改数据目录 | 按约定延迟、停止或暂停，不突然大批永久删除 |
| 回收站到期但文件又被使用 | 恢复或保留，不永久删除 |
| 永久删除后尝试撤销 | 明确告知不可恢复，不生成虚假的成功状态 |

必要验证使用现有测试框架，补充涉及引用、事务、路径及并发的关键测试，再进行普通/智能画布和设置页的实际联动检查。不调用付费生成，生成流程使用模拟上游，不为低风险文案重复扩展测试。

## 14. 推荐确认范围

建议确认实施完整的三阶段方案，采用默认关闭、连续未引用 30 天、回收站 7 天、外部目录排除、资产库主动保留、撤销和任务保护、永久删除前再次验证的规则。

在全部必要保护接入并验收之前，自动执行开关保持不可用或仅提供只读扫描，不能以部分完成的引用索引对真实资料执行删除。
